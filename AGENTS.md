# AGENTS.md

Instructions for AI coding agents working **on** fullgpu-render. To **use** it to make a video, read
[`skills/fullgpu-render/SKILL.md`](skills/fullgpu-render/SKILL.md) and [`docs/llms-full.txt`](docs/llms-full.txt) instead.

## What this is

A programmatic video renderer that keeps every frame on an NVIDIA GPU: NVDEC decode, wgpu compositing (WGSL shared
with a WebGPU variant), NVENC encode. JavaScript describes the video and compiles it to a layout JSON (draw list per
frame); a Rust engine renders that JSON.

```
SDK composition (.mjs) ─┐
                        ├─▶ sdk/compose.mjs compile() ─▶ layout JSON ─▶ native/ (Rust) ─▶ MP4
Remotion entry (.tsx) ──┘    ▲
  └─ sdk/react/: esbuild bundle → own React runtime → Yoga layout (text measured by `fullgpu-render --measure`)
```

## Layout

| Path | What |
|---|---|
| `sdk/cli.mjs` | `fullgpu` CLI: render, still, compositions, check, doctor, `--json`; finds or downloads the engine |
| `sdk/compose.mjs` | SDK nodes and `compile()` to the engine's layout JSON |
| `sdk/animation.mjs` | `interpolate`, `spring`, `Easing`, `interpolateColors` (checked against Remotion as an oracle) |
| `sdk/react/` | Remotion compatibility: `runtime.mjs` (JSX + hooks, pure per-frame evaluation), `remotion.mjs`, `react.mjs`, `css.mjs` (CSS values), `layout.mjs` (Yoga → SDK nodes), `project.mjs` (esbuild), `measure.mjs` |
| `native/src/` | Engine: `main.rs` (scheduling, `--measure`), `gpu.rs` (wgpu compositor), `text.rs` (cosmic-text), `ffmpeg.rs`, `layout.rs` (JSON schema) |
| `shaders/` | WGSL used by both engines; `compose.wgsl` is the compositor |
| `browser/` | WebGPU + WebCodecs engine (same shader) and its local server |
| `scene/`, `tools/bench.mjs` | Benchmark scene and measurement tooling |
| `remotion-baseline/` | The same benchmark scene as a real Remotion project (reference and acceptance test) |
| `examples/` | SDK examples and `examples/remotion-project` (rendered GIFs in `docs/examples/`) |
| `docs/llms/llms-full.template.md` → `docs/llms-full.txt` | Reference for LLMs, generated by `npm run llms` |
| `skills/fullgpu-render/`, `.claude-plugin/` | Agent skill, installable as a Claude Code plugin |

## Commands

```bash
npm install
npm test                                   # all JS tests (no GPU needed)
npm run build                              # cargo build --release of the engine
cd native && cargo test --release          # Rust tests; add `-- --include-ignored` on a machine with an NVIDIA GPU
npm run llms                               # regenerate docs/llms-full.txt after changing the CLI, the API or CSS support
claude plugin validate .                   # after touching .claude-plugin/ or the skill
npm run media                              # synthetic inputs in media/ (needs ffmpeg)
node sdk/cli.mjs still examples/remotion-project/src/index.tsx out/x.png --frame 75 --public-dir examples/remotion-project/public
```

The CLI prefers `native/target/release/fullgpu-render` over the downloaded engine, so a local `npm run build` is what
`node sdk/cli.mjs` runs.

## Rules

- **Tests first.** Every feature or bug fix starts with a failing test (`node:test` in `*.test.mjs` next to the code,
  `#[test]` in Rust; GPU tests are `#[ignore = "necesita una GPU NVIDIA"]`).
- **Look at the frames.** For anything visual, render a still before and after (`fullgpu still`) and look at it. For
  Remotion fidelity, compare with `npx remotion still ... --gl=swangle` (from `remotion-baseline/`) using ffmpeg SSIM.
  Never run two Remotion renders at once; prefer stills over full Remotion renders (they are heavy on this laptop).
- **Do not regress existing output.** Engine changes must leave existing layouts pixel-identical unless intended:
  render the same layout JSON with the previous release binary and compare (SSIM 1.0).
- **Keep frames on the GPU.** Say whether a change adds a CPU round trip; include `tools/bench.mjs` numbers for render
  path changes, and check `nvidia-smi` clocks (the laptop GPU throttles).
- **New fields are optional.** The layout JSON and SDK options stay backward compatible: new fields get serde defaults
  and SDK defaults that keep the old behavior (see `shadow.clip`).
- **Unsupported CSS warns, never crashes.** In `sdk/react/layout.mjs`, anything the engine cannot draw goes through
  `warn()` and is skipped, so `fullgpu check` can report it.
- **Docs follow the code.** After changing the CLI, exported API or supported CSS, run `npm run llms`; the test in
  `tools/llms.test.mjs` fails otherwise. Update `skills/fullgpu-render/SKILL.md`, `README.md` and `CHANGELOG.md` when
  behavior changes.
- **Style.** Source comments are in Spanish, like the existing code; README, docs, CLI messages and errors are English.
  Match the surrounding code's naming and comment density.
- **Commits.** Small commits with a descriptive message. No `Co-Authored-By` or other AI attribution lines.
- **Never commit** `media/`, `out/`, third-party logos or private material (`.gitignore` covers `media/` and `out/`).

## Releasing

The CLI downloads the engine binary of the release that matches `package.json`'s version, so any engine change ships
as a release:

1. Bump the version in `package.json`, `package-lock.json`, `native/Cargo.toml` (+ `Cargo.lock`) and
   `.claude-plugin/plugin.json` (a test checks the plugin matches).
2. Add the `CHANGELOG.md` entry, run `npm test` and the Rust tests with `--include-ignored`.
3. Push `main`, then tag `vX.Y.Z` and push the tag: `.github/workflows/release.yml` builds and attaches the Windows
   and Linux binaries.
4. Verify from an empty folder: `npm install github:WassimAarab08/fullgpu-render#vX.Y.Z` and render something.
